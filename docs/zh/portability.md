---
title: 可移植性
description: Open Interpreter 如何采用共享的代理标准并避免产品锁定。
---

Open Interpreter 的目标是参与共享的代理生态系统，而不是为指令、技能和工作流创建封闭孤岛。当存在实用的跨工具标准时，Open Interpreter 应直接读取该标准，并以其他兼容工具也能使用的形式保留内容。

这是产品方向，也是一项工程约束；并不表示每一种运行时状态都已经拥有通用格式。

## 原则

- 优先采用成熟且与工具无关的协议和目录约定，而不是 Open Interpreter 专用的替代方案。
- 让用户编写的指令、技能和配置保持可读、可检查。
- 就地读取共享内容，无需导入或创建私有副本。
- 在迁移期间保留对旧产品路径的兼容读取。
- 当不存在共享的实时格式时，提供导出和迁移能力。
- 仅将尚无法通过共享标准安全表示的密钥、缓存、索引、日志和运行时状态保存在产品专用存储中。

## 当前共享界面

| 能力 | 共享界面 |
| --- | --- |
| 项目指令 | `AGENTS.md` |
| 项目技能 | `.agents/skills/` |
| 个人技能 | `~/.agents/skills/` |
| 工具集成 | 模型上下文协议（MCP） |
| 编辑器和客户端集成 | 代理客户端协议（ACP） |
| 程序化执行 | Codex 兼容的 exec 协议 |

这些位置和协议应当无需把用户数据转换成 Open Interpreter 专用格式即可使用。

## 产品专用状态

Open Interpreter 目前将配置、凭据、会话历史、日志、缓存和守护进程状态保存在 `~/.openinterpreter` 或操作系统凭据存储中。其中一部分状态本身就是产品专用的；另一部分可能会在安全且被广泛采用的共享标准出现后迁移过去。

旧的 `~/.openinterpreter/skills/` 目录仍然可读，以免现有设置失效。对于新的个人技能，推荐使用共享目录 `~/.agents/skills/`。

## 这对更改意味着什么

在增加新的产品自有文件格式或目录之前，应先确认成熟的代理、编辑器或操作系统标准是否能够表示同一份数据。如果仍然需要产品专用格式：

1. 在可行时使用简单且有文档说明的数据格式。
2. 保持产品专用边界尽可能小。
3. 为用户编写的数据提供迁移或导出路径。
4. 避免让产品专用副本成为唯一可用的数据源。

衡量可移植功能的标准很简单：用户应当能够理解自己的数据存放在哪里，能够在其他兼容工具中复用标准化的部分，并且在离开 Open Interpreter 时不会丢失自己编写的内容。
